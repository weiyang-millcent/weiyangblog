# 数字轰炸题目复现

## 前言

题目给出了连续九天收到的数字，每一天的数据都是一组位于 `0～146` 之间的整数，同时给出了以下提示：

```text
“这最多也只能是个点啊……”
“什么坐标轴？”
“方格上更清晰”
```

从这些提示可以判断，每一个数字并不是需要直接转换的字符，而是在表示像素点的位置。我们需要找到这些数字在坐标系中的含义，再将所有点绘制出来。

---

## 一、观察数据特征

首先观察九天的数据范围：

```text
最小值：0
最大值：146
```

如果从0开始计数，横向一共有：

```text
146 - 0 + 1 = 147
```

个位置。

题目又恰好给出了九天的数据，因此可以作出以下猜测：

```text
每天收到的数字 → 横坐标x
第几天         → 纵坐标y
```

最终应该建立一张：

```text
宽147格 × 高9格
```

的点阵图。

---

## 二、容易走错的方向

因为：

```text
147 = 7 × 21
```

所以一开始可能会尝试把每天的数据分别放进一张 `7×21` 或 `21×7` 的网格。

但这样得到的九张图都没有明显意义。结合题目中的“第1天”到“第9天”可以发现，天数本身不只是用来分隔数据，而是在提供纵坐标。

正确结构不是：

```text
每天单独生成一张7×21图片
```

而是：

```text
九天共同组成一张147×9图片
```

---

## 三、确定坐标关系

程序通常从0开始计数，因此将九天分别映射到纵坐标 `0～8`：

| 题目中的天数 | 纵坐标 |
|---:|---:|
| 第1天 | `y = 0` |
| 第2天 | `y = 1` |
| 第3天 | `y = 2` |
| 第4天 | `y = 3` |
| 第5天 | `y = 4` |
| 第6天 | `y = 5` |
| 第7天 | `y = 6` |
| 第8天 | `y = 7` |
| 第9天 | `y = 8` |

例如，第1天开头的数据为：

```text
25 31 32 36 37
```

它们对应的点就是：

```text
(25, 0)
(31, 0)
(32, 0)
(36, 0)
(37, 0)
```

第2天的数据则全部位于 `y=1`，后面依次类推。

---

## 四、使用Python绘制字符

这道题可以使用 Python 将坐标直接绘制到终端中。

首先将每天收到的数字分别放入列表：

```python
days = [
    # 第1天
    [25, 31, 32, 36, 37, 40, 43, 44, 45, 46, 47,
     55, 56, 57, 58, 59, 61, 69, 98, 106, 120,
     129, 138, 139, 140, 143, 144],

    # 第2天
    [25, 30, 35, 43, 59, 61, 68, 69, 97, 98, 106,
     120, 128, 129, 137, 141, 145],

    # 此处继续按照题目顺序放入第3天至第9天的数据
]
```

完整脚本可以直接下载：

[digital_bomb_solve.py](/files/digital_bomb_solve.py)

脚本中最关键的绘制部分如下：

```python
width = max(max(day) for day in days) + 1
height = len(days)

for day in days:
    points = set(day)
    print("".join(
        "##" if x in points else "  "
        for x in range(width)
    ))
```

下面逐行理解这段代码。

### 1.计算画布宽度

```python
width = max(max(day) for day in days) + 1
```

先找出九天数据中的最大值146。因为坐标从0开始，所以需要加1：

```text
width = 146 + 1 = 147
```

### 2.计算画布高度

```python
height = len(days)
```

`days` 中有九个子列表，因此：

```text
height = 9
```

### 3.每一天对应一行

```python
for day in days:
```

每次循环处理一天的数据，也就是绘制点阵图中的一行。

### 4.提高查找效率

```python
points = set(day)
```

把当天的数字转换为集合。这样在判断某个横坐标是否存在时，可以直接使用：

```python
x in points
```

### 5.判断像素是否填充

```python
"##" if x in points else "  "
```

如果横坐标 `x` 出现在当天的数据中，就输出两个井号：

```text
##
```

否则输出两个空格：

```text
  
```

这里使用两个字符表示一个像素，是因为终端中的字符通常比行高窄。横向输出两个字符后，点阵比例更容易辨认。

## 六、读取点阵字符

从左到右读取点阵，可以得到：

```text
moectf{i5_7h1s_gr1d_ch4r?}
```

其中使用了一些 Leetspeak 替换：

```text
i5   → is
7h1s → this
gr1d → grid
ch4r → char
```

整体内容可以理解为：

```text
is_this_grid_char?
```

---

## 七、容易看错的字符

花括号后的第一个字符很容易被误认为数字 `1`。

这个字符的点阵为：

```text
.#.
...
##.
.#.
.#.
.#.
###
```

可以看到最上方有一个独立的点，而主体从第三行开始，所以它是小写字母：

```text
i
```

它后面的字符才是数字：

```text
5
```

因此正确开头是：

```text
i5
```

而不是：

```text
15
1S
```

## 九、总结

本题的完整思路如下：

```text
观察数字范围为0～146
        ↓
确定横向共有147个位置
        ↓
注意题目一共给出9天数据
        ↓
将数字作为横坐标
        ↓
将天数作为纵坐标
        ↓
建立147×9的点阵图
        ↓
填充对应坐标并读取字符
```

题目中的提示也分别对应了解题过程：

```text
“最多也只能是个点”
→ 每个数字代表一个像素点

“什么坐标轴？”
→ 数字和天数分别对应横纵坐标

“方格上更清晰”
→ 将坐标放入网格后才能清楚读取点阵文字
```

遇到类似题目时，如果数据由多组整数构成，并且题目中出现“点、坐标、方格、像素”等提示，可以优先尝试把组号作为一个坐标轴、组内数值作为另一个坐标轴，再绘制二维点阵。
