# 不可逆算法题目复现

## 题目分析

程序启动后会调用一个很大的函数，然后提示输入完整 Flag。输入会先检查长度和 `flag{` 前缀，再进行 SHA-256 校验。因此直接逆哈希不可行，关键在于前面那个巨大的控制流图。

## 控制流图中的信息

IDA 提示图超过节点限制时，可以切换到文本模式；但这里的巨大函数并不是普通业务逻辑，而是由大量基本块组成的 **7×256 位图**。依次读取基本块的跳转关系，把满足条件的节点记为 `1`，其余记为 `0`，每 8 位还原成一个字节。

还原出的字节串就是题目作者埋在 CFG 中的“收据”，内容为：

```text
flag{cfg_reveals_hash_value_1}
```

将它输入程序即可得到 `correct`。这个题的考点是识别异常控制流、从 CFG 提取隐藏数据，以及区分“不可逆”的 SHA-256 校验和可恢复的外部信息。

## 详细分析过程

### 1. 先判断输入校验的位置

在 IDA 中从字符串 `CFG receipt rendered above` 和 `Enter the complete flag` 反向查找交叉引用，可以定位到主函数。主函数的逻辑很短：调用一个负责绘图/收据生成的大函数，然后读取输入，最后把输入交给校验函数。这里的 SHA-256 只负责验证结果，并不会把 Flag 直接“解密”出来。

因此不能把 SHA-256 当作需要爆破的密码。正确思路是先分析校验前的输出来源，看看程序是否已经把正确答案以其他形式放进了二进制。

### 2. 为什么要观察 CFG

打开大函数的 Graph View 后，IDA 会提示节点超过显示上限。切换到 Text View 后可以看到，大量基本块重复执行非常相似的跳转逻辑，正常业务代码不会有这么规则的规模。结合题目名称“不可逆算法”和提示文字，可以判断这个函数更像一张被展开的位图，而不是实际算法。

将每个基本块看作一个节点，按照程序遍历顺序记录节点是否满足目标条件，得到一个由 `0/1` 组成的序列。序列宽度为 256，行数为 7，所以总长度为 `7 × 256 = 1792` 位。

### 3. 脚本还原位图

实际提取时只需要记录满足条件的节点位置，并把每 8 个 bit 合并为一个字节：

```python
bits = []
for row in range(7):
    for col in range(256):
        bits.append(1 if condition(row, col) else 0)

data = bytes(
    sum(bits[i + j] << (7 - j) for j in range(8))
    for i in range(0, len(bits) - 7, 8)
)
print(data.rstrip(b"\x00").decode())
```

得到可读的 `flag{...}` 后，再运行原程序进行验证即可。这个过程的关键不是逆 SHA-256，而是利用控制流本身携带的额外信息。

## 小结

遇到超大的控制流图时，先判断它是否真的承担业务逻辑。如果基本块结构高度重复、节点数量异常，往往是在用 CFG 存储位图、字符表或状态机。校验函数中的不可逆哈希可能只是最后一道确认，真正的答案可能已经隐藏在程序结构里。
